# Search indexing and visitor map

The home page is `/`. `/cv/` and `/resume/` redirect to it. The navigation contains only Publications.

## Search indexing

The site provides a descriptive title and meta description, a canonical URL, Person / WebSite / ProfilePage structured data, links to GitHub and Google Scholar, and a robots.txt pointing at the sitemap generated by jekyll-sitemap.

After publishing, add `https://lhy101.github.io/` as a URL-prefix property in Google Search Console. If HTML-tag verification is selected, put its token in `google_site_verification` in `_config.yml`. Submit `https://lhy101.github.io/sitemap.xml`, inspect the home URL, and request indexing. Search engines control recrawling and ranking; these edits do not guarantee a particular rank.

Link back to the home page from the Google Scholar profile and the PKU DAIR member page, when those profiles can be edited. These identity links help distinguish this Haoyang Li from people with the same name. No account or external profile is changed by this implementation.

## Visitor map

1. Create a ClustrMaps map for `https://lhy101.github.io/` and copy its generated embed code.
2. Copy only the value of `d=` from that code into `site_id` in `_data/visitor_map.yml`.
3. Build and publish. The map appears below the awards and uses the site's green and white palette.

An empty ID hides the entire section and sends no requests to ClustrMaps. Local previews are excluded. The map records real visits only after the ID is configured and the site is published; it does not contain sample locations. Enabling it loads the third-party ClustrMaps service, which determines approximate visitor locations from network requests.

If ClustrMaps changes its embed format, use the current code provided by its dashboard and update `assets/js/visitor-map.js`. The external service was not reachable from the development environment, so live map rendering still requires verification after configuration.
